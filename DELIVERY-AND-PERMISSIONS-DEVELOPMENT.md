Shared records now include all twelve existing record kinds plus properties. Workspace viewer/editor/approver/admin capabilities cap record grants. An admin can restrict a property or record to read/edit/issue grants for existing staff; property restrictions apply to children too. Every public read/write/issue/invite/revoke/history endpoint applies the policy. Restricted data is filtered from sync lists; previously synced records no longer returned are hidden from the active workspace, with unsent recovery data retained. Access changes are audited. Administrators have explicit recovery access. Offline copies, backups and prior exports cannot be remotely recalled; retention/device management remains an operational requirement.

Invitations validate the intended email and atomically queue delivery to an owner-configured isolated HTTPS customer origin. The new staff API returns queue/request metadata, never a bearer token. Email code verification is required before reading or acknowledging. Codes expire after ten minutes, have five attempts and are single-use; resend is limited to once a minute and five per hour/request. Proofs are hashed, short-lived and bound to the invitation. Legacy bearer-only read/accept APIs are denied to anonymous and staff roles after upgrade. Exact digest/name/consent repeats return the same acknowledgement without duplicate signed events. Audit records mailbox, verification time, exact digest, consent, self-declared name and server signing time. Verification proves mailbox access, **not** a person's legal identity or authority. TLS, gateway IP rate limits and HTTP CSP/frame/no-store headers are required before a hosted customer route can be exposed. The UI remains loopback-only and is not deployed.

`controlled-pdf.js` verifies the SHA-256 canonical snapshot before producing certificates/PAT/lighting/quotations with frozen site/results/scope and verified acknowledgement evidence. The customer screen downloads the PDF and JSON receipt; tokens/proofs are excluded. These are electronic acknowledgement evidence PDFs. **Cryptographic PDF signatures/PAdES, trust certificates and qualified identity verification are not implemented.** They require an approved signing/identity provider and key custody. Company/legal/technical review still determines whether any document may be used as statutory certification.

The durable email outbox supports invitations, verification codes, acknowledgement receipts and opt-in 30/7-day reminders. Reminder recipients must have previously acknowledged through mailbox verification in the same workspace. Staff can enable/disable subscriptions in the test panel. A UTC scheduler catches up inside each lead window, skips the older 30-day reminder once inside seven days, excludes completed/cancelled records and revalidates date/subscription before claiming. Stable unique keys prevent repeat scheduling across revisions. Changed dates produce a new reminder cycle and cancel stale queued work.

Worker claims are atomic with SKIP LOCKED, lease fencing, a two-minute lease, five attempts, bounded exponential retry and terminal failures. `server/mail-worker.cjs` sends via Resend using a stable idempotency key per mail and limits retries to 23 hours within Resend's documented 24-hour idempotency window. Unknown responses retain the identical operation. The provider must preserve that contract; after its safe retry window, reconcile manually rather than recreating mail. Message secrets are scrubbed on completion/expiry/cancellation. Delivery events distinguish provider acceptance from delivery; mailbox delivery/bounces are **not verified**. A claimed message can race a later cancellation, as with any external send; cancellation cannot recall an already accepted email.

Worker RPCs are service-role-only; do not place worker keys in browser configuration. No credentials or worker/scheduler/provider are configured here, and no real messages are sent.
